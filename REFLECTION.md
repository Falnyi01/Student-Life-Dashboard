# Reflection on Building the Student Life Dashboard with GitHub Copilot

## 1. What did you ask Copilot to help you build? How did you break down the problem?

I asked Copilot to help me build a student planner that combined three core features in one place: a calendar, a weekly schedule, and a to-do list. The main goal was to create an app that could help manage academic life in a single dashboard without needing a separate app for each feature.

I starte by describing what I wanted to Coilot so it would have a direction of how to code when I gave it other prompts. I broke the work down into smaller parts so it felt manageable and easier to test. First, I focused on the calendar and event creation flow. Then I moved to the weekly schedule and the time-grid view. After that, I added the to-do system and assignment reminders. Lasty, I went back and refined the weekly summary so it could calculate how much time was spent on events and how much free time users had.

This step-by-step approach made it easier to ask for help on each feature and help me keep organized.

## 2. How did your approach to asking questions change as you worked?

At first, I asked broad questions about the overall app structure. As countiued to work, my questions became more specific and focused on one problem at a time. For example, I went from asking how to structure the app or build the whole calender to asking how to fix a particular issue, like current-day items not showing up, assignment date validation, or weekly time blocks not working correctly.

This change was important because the app became more complex as features were added. I began asking targeted questions such as: what is causing this bug, how should the data be structured, and how do I fix a bug.

## 3. What parts of the development process with GitHub Copilot surprised you?

The biggest surprise was when Copilot could actually run my code and test it in the browser for me. I was watching it make changes, refresh the app, and check whether the features were working. It felt really strange and a little unsettling because it looked like it was taking over my laptop and doing work on my project while I was just watching.

The AI was no longer just suggesting code — it was actively helping me test and verify the app in real time. I was surprised by how much control it seemed to have over the browser workflow, and it made me feel like it could do almost anything with my project, or laptop once it had the right instructions!

That was when it felt different from normal coding help. It was not just giving me ideas anymore; it was helping run the app and test the behavior in a way that felt a lot more hands-on and powerful.

## 4. What did you learn about the technology you used that you didn't know before?

I learned how HTML, CSS, and JavaScript work together to create an actual web app instead of just separate files. HTML gives the structure of the page, CSS makes it look like a polished interface, and JavaScript adds the logic and behavior that make it interactive.

Some of the biggest things I learned through this project were:

- how to use JavaScript to update the page dynamically as the user interacts with it
- how CSS controls layout, spacing, colors, and visual structure
- how event data, calendar dates, and schedule events all connect to each other
- how browser storage works so information can be saved even after the browser is closed
- how a single-page app can organize multiple views such as a calendar, weekly planner, and to-do list in one experience

## 5. What would you do differently if you had to build this again?

If I had to build this again, I would start by planning the app data model more carefully before coding each feature. I would define the event, task, assignment, and weekly schedule data structures earlier so the different views could all use the same information consistently.

I would also be more intentional about documentation from the beginning, because keeping track of feature changes and bug fixes became important as the app grew.

## Summary

This project taught me that Copilot can be a very effective development partner when used strategically, but it also showed me how powerful and surprising AI-assisted coding can feel when it begins testing and running the app in the browser in real time. Watching it work through the project, refresh the page, and check functionality made me realize how much the development process can change when the tool is not just suggesting code but actively helping verify it.

I also learned that HTML, CSS, and JavaScript do not work independently — they come together to build the full experience of an app. HTML creates the structure, CSS shapes the design, and JavaScript adds the interactivity and logic that make the planner functional. Overall, this project showed me how much can be learned by building something real, testing it in the browser, and refining it through feedback and iteration.
